## 3. Remaining Drift (Next Pickup List)

Ordered by impact / risk.

### 3.1 Raw `<input>` / `<textarea>` / `<select>` not using `@quikit/ui` primitives
Counts in `apps/quikscale/app`:
- `<input>` (excluding checkbox/radio): **27**
- `<textarea>`: **34**
- `<select>`: **54**

Approach: file-by-file replace with `Input` / `Textarea` / `Select` primitives. Lower priority than drawers because the primitive surface is already correct — these just bypass the primitive while applying matching Tailwind classes by hand.

Risk: low. Mechanical. Touch one form per PR.

### 3.2 Inline `<svg>` literals (81 occurrences)
Replace with `lucide-react` icons. Many duplicates of `Plus`, `X`, `Check`, `ChevronDown`, `Trash`, `Pencil`, `Search`, `Filter`.

Risk: low–medium. Some inline SVGs use custom paths (custom doodles, brand marks). Keep those — replace only mechanical lucide-equivalent icons.

### 3.3 KPIModal / LogModal / PriorityLogModal → `<RightPanel>` (DEFERRED)
Three large drawers (300–500 LOC each) in:
- `app/(dashboard)/kpi/components/KPIModal.tsx`
- `app/(dashboard)/kpi/components/LogModal.tsx`
- `app/(dashboard)/priority/components/PriorityLogModal.tsx`

Each has heavy custom logic (weekly value entry grid, log timeline w/ optimistic updates, priority comments). Migration is high-value (most-used drawers in app) but high-risk if done unattended — could leak the locked-table palette into `accent-*` tokens.

Recommendation: do one at a time, with a manual smoke test after each, in 3 separate small PRs.

### 3.4 Typography scale rollout (DEFERRED)
`packages/ui/styles/globals.css` defines `.text-h1` … `.text-b3` utilities. Current consumers: **0**. Rollout would touch ~50 files.

Recommendation: do not adopt now. Either delete the utilities or commit to a focused rollout sprint with screenshot diffs per page.

### 3.5 Page-header consistency
Pages use 3 different header patterns: `<h1 className="text-2xl font-bold">`, `<h1 className="text-xl font-semibold">`, `<h1 className="text-lg font-bold">`.

Recommendation: extract `PageHeader` primitive into `@quikit/ui` once typography scale lands (couples cleanly to it).

### 3.6 Avatar variants (NOT migrated)
Sizes in use: w-5/h-5, w-6/h-6, w-8/h-8, w-10/h-10, w-14/h-14, w-16/h-16. After review these are contextually correct (pickers / table-row inline / menu / iconic / empty state / profile). Standardising to fewer sizes would flatten visual hierarchy.

Recommendation: **leave as-is**. Document the size scale in `@quikit/ui/components/avatar.tsx` doc comment so new code picks the right size.

### 3.7 `rounded-sm` swatches (NOT migrated)
6 hits, all on 10–12px legend chips in performance/(scorecard|trends) and opsp/CritBlock. Promoting to `rounded-md` would over-round. Leave.

### 3.8 z-index scale (EXCLUDED per user instruction)
Out of scope this pass.
