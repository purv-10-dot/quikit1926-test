## 5. Formula Verification Deep-Dive

### 5.1 Stock Ledger
- **Running balance:** never stored, always `SUM(qtyIn) - SUM(qtyOut)` grouped by (tenant, project, location, item). Verified non-negative in 2/2 cells.
- **Moving-avg rate:** `Σ(amount) / Σ(qtyIn)` over inbound rows at that location. Used by DPR post and Stock Valuation report.
- **Transfer pairs:** each transfer writes two rows with same `transactionRefId` — invariant `Σout == Σin` verified, 0 unbalanced.

### 5.2 RAB Progressive Billing
Per line:
- `priorCumulativeQty = Σ prior RAB lines' currentPeriodQty` (same project, same boqItem, status ∈ {draft, submitted, approved, paid})
- `currentPeriodQty = cumulativeQtyDone − priorCumulativeQty` (must be ≥ 0)
- `currentPeriodAmount = currentPeriodQty × rate` (rate snapshot from BOQ at RAB creation)
- **Verified:** 1 RAB × 3 lines, all pass

### 5.3 Payroll Calculation
Per employee:
- Permanent: `monthlyWage × (daysPresent / workingDays)`
- Daily wage: `daysPresent × dailyWage`
- Contract: `hoursWorked × hourlyWage`
- `daysPresent = count(P) + 0.5 × count(HD)`
- `totalGross = Σ basicAmount`, `totalNet = Σ (basicAmount − deductions)`

### 5.4 Project P&L
- `revenue = Σ ClientInvoice.total (non-cancelled)`
- `billsCost = Σ VendorBill.total`
- `materialsCost = Σ StockLedger.amount where transactionType='dpr_consumption'`
- `expensesCost = Σ Expense.amount (non-cancelled)`
- `labourCost = Σ payroll lines × (project_days / total_paid_days)` from finalized/paid runs
- `totalCost = bills + materials + expenses + labour`
- `margin = revenue − totalCost`, `marginPct = margin / revenue × 100`

### 5.5 AR/AP Aging Buckets
Days overdue from `dueDate` (fallback `invoiceDate` / `billDate`):
- `≤ 0` → Current
- `1–30` → d30
- `31–60` → d60
- `61–90` → d90
- `> 90` → over90
Outstanding per row: `total − paidAmount`.

### 5.6 Vendor Performance
- `grnOnTimePct = count(grn.grnDate ≤ po.deliveryDate) / grnCount × 100`
- `qualityAcceptPct = count(grnLine.qualityStatus='accepted') / totalLines × 100`

### 5.7 Credit / Debit Note Auto-Apply
When invoice/bill referenced:
- `invoice.paidAmount += note.amount` (capped at total)
- Status transitions: `sent → partial → paid` / `approved → partial → paid`
- Entire flow atomic via `db.$transaction`

### 5.8 Approval Gate Logic
```
matchingRules = rules.filter(r => r.docType == docType && (r.minAmount == null || amount >= r.minAmount))
if matchingRules.length == 0: ALLOW
if any approved request exists for (docType, docId): ALLOW
else: DENY with 403 APPROVAL_REQUIRED
```

### 5.9 Number Sequence (New this session)
- `nextNumber({tenantId, prefix, fy})` uses Prisma `upsert` with `counter: { increment: 1 }` — atomic
- FY key encoded with sentinel empty-string to allow compound uniqueness on nullable field
- **Prevents collision** of `Date.now().slice(-6)` under concurrent load
