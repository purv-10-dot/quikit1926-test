## 1. Leads

**Purpose:** Core entity for managing prospective customers through a configurable sales pipeline.  
**Route:** `/leads`  
**Primary permission module:** `leads`  
**Database model:** `CrmLead`

### 1.1 Lead Creation

Multi-step form with 5 steps: Lead Info → Company → Contact → Requirements → Purchase & Follow-up. Captures 50+ fields. On save: triggers lead scoring, auto-creates a follow-up task, logs system activities, fires workflow automation triggers, and writes a CREATE change-log entry.

| | |
|---|---|
| **API** | `POST /api/leads` |
| **Validator** | `createLeadSchema` |
| **Permission** | `leads:create` |
| **Key fields** | name, email, phone, mobile, company, jobTitle, leadType, source, stage, status, score, ownerId/ownerName, accountId, country, industry, secondaryEmail, website, linkedinUrl, annualRevenueDisplay, descriptionInformation, topic, technology, requirementDetails, sourceDetails, contactLinkedinUrl, nextFollowUpAt, lastContactedAt, followupNotes, internalRemarks, budgetAmount, budgetCurrency, purchaseTimeframe, leadQuality, externalId, sourceSystem, originChannel, isStarred, followupPriority, address fields, lat/long, dynamicFields |
| **Side-effects** | Lead scoring calculation, auto follow-up task, system activity log, workflow trigger `onLeadCreated` |

### 1.2 Lead Editing

Full field PATCH with field-level permission masking. Supports partial updates; merges `dynamicFields`. Auto-recalculates score if enabled. Records before/after change-log entry.

| | |
|---|---|
| **API** | `PATCH /api/leads/[id]` |
| **Validator** | `updateLeadSchema` |
| **Permission** | `leads:edit` |
| **Side-effects** | Score recalculation, change log, workflow trigger `onLeadUpdated` |

### 1.3 Soft Delete (Move to Trash)

Sets `deletedAt` timestamp. Lead disappears from default queries but is recoverable. Does not cascade-delete child records.

| | |
|---|---|
| **API** | `DELETE /api/leads/[id]` |
| **Permission** | `leads:delete` |

### 1.4 Restore from Trash

Clears `deletedAt`. Records RESTORE change-log entry and fires workflow trigger.

| | |
|---|---|
| **API** | `POST /api/leads/[id]/restore` |
| **Permission** | `leads:delete` |

### 1.5 Permanent Delete (Admin only)

Hard-deletes the row and FK-cascaded children. Soft-orphans linked activities (`relatedOrphanedAt`) to preserve the audit trail. Requires the lead to already be in trash (two-step destructive flow).

| | |
|---|---|
| **API** | `DELETE /api/leads/[id]/permanent` |
| **Permission** | Administrator role only |

### 1.6 List View (Lead Explorer)

Paginated, sortable table with configurable and freezable columns (persisted in `localStorage`). Quick search, page sizes 10/25/50/100, export button, trash-mode banner.

| | |
|---|---|
| **API** | `GET /api/leads` + `POST /api/leads/filter` |
| **Permission** | `leads:view` |
| **UI component** | `LeadsExplorer` |

### 1.7 Kanban View (Pipeline Board)

Drag-and-drop cards grouped by pipeline stage. Up to 500 cards per column. Owner filter. Load-more per column. Real-time updates via SSE.

| | |
|---|---|
| **API** | `GET /api/leads/kanban/board` |
| **Permission** | `leads:view` |
| **UI component** | `lead-kanban.tsx` |

### 1.8 Saved Views (Named Filters)

Create/update/delete named filter views stored server-side. One view can be the default (star-pinned). Displays lead counts per view.

| | |
|---|---|
| **API** | `GET/POST/PATCH/DELETE /api/leads/saved-views` |
| **Permission** | `leads:view` |

### 1.9 Advanced Filter Builder

Multi-condition filter with AND/OR (`matchMode`). Supports text, number, date, select, boolean fields. Operators per type (contains, eq, gt, between, isEmpty, etc.). Supports filtering custom `dynamicFields` via JSON-path queries.

| | |
|---|---|
| **API** | `POST /api/leads/filter` |
| **Validator** | `leadFilterRequestSchema` |

### 1.10 Quick Search

Real-time text filter across name, email, company, phone, mobile, jobTitle. Case-insensitive.

### 1.11 Lead Detail Page (360 View)

Single aggregated server call returning lead + activities + tasks + notes + opportunities + call logs + attachments + SLA tracking. Rendered as a multi-tab shell.

| | |
|---|---|
| **API** | `GET /api/leads/[id]/full` |
| **Permission** | `leads:view` |
| **UI component** | `lead-dashboard-shell.tsx` |

### 1.12 Stage Pipeline Stepper

Visual indicator showing all pipeline stages, current stage highlighted, conversion probability per stage. Click-to-transition supported.

### 1.13 Overview Tab

Summary of recent activities, open tasks, notes, linked opportunities with quick counts.

### 1.14 Unified Timeline Tab

Chronological feed merging activities, calls, emails, notes, tasks, stage changes, documents. Filterable by type. Supports orphaned activities.

| | |
|---|---|
| **UI component** | `unified-timeline.tsx` |
| **Service** | `unified-timeline.ts` — `buildUnifiedTimeline()` |

### 1.15 Activities Tab

Log and view Call, Email, Meeting, Task, Other activities. Fields: subject, outcome, activityCode, detailNotes, occurredAt, followUpAt.

### 1.16 Call History Tab

All call logs linked to the lead — direction, status, duration, start time.

### 1.17 Call Disposition Tab

Log call outcome using tenant-configured disposition codes. Linked to call logs. Ordered by code.

| | |
|---|---|
| **UI components** | `lead-call-disposition-tab.tsx`, `call-disposition-modal.tsx` |

### 1.18 Tasks Tab

View and create tasks linked to this lead. Sorted by status then due date.

### 1.19 Notes Tab

Long-form text notes linked via `relatedKind='Lead'`.

### 1.20 Opportunities Tab

All opportunities linked to this lead — name, stage, amount, currency, stage label.

### 1.21 Documents Tab

Upload, list, download, delete files attached to this lead.

| | |
|---|---|
| **API** | `GET/POST /api/leads/[id]/attachments`, `GET /api/leads/[id]/attachments/[aid]/download` |

### 1.22 Analytics Tab

Trend charts for the last 14 days: activity trend, engagement trend, score trend, response time hours, conversion progress by stage.

| | |
|---|---|
| **Service** | `lead-analytics.ts` — `buildLeadAnalytics()` |
| **UI component** | `analytics-tab.tsx` |

### 1.23 Change Log Tab

Full audit trail — action (CREATE/UPDATE/DELETE/RESTORE/PERMANENT_DELETE), before/after JSON snapshots, changed field list, user name, timestamp. Filterable by action, user, field, date range.

| | |
|---|---|
| **API** | `GET /api/leads/[id]/changelog` |
| **UI component** | `lead-change-log-drawer.tsx` |

### 1.24 Stage Transition

Move lead between pipeline stages. Validates target stage/status exists in the org's pipeline config and that the status is allowed for the stage. Logs a `LeadStageChange` activity, records change log, fires workflow trigger.

| | |
|---|---|
| **API** | `POST /api/leads/[id]/transition` |

| **Permission** | `leads:edit` |

### 1.25 Lead Conversion

Convert lead to Contact, optionally creating an Account and/or Opportunity in the same transaction. Re-links all activities, tasks, notes, call logs to the new Contact. Sets status → `"Converted"` with `convertedAt` timestamp.

| | |

### 1.26 Lead Scoring (Automated)

Rules-based 0–100 score. Components: fit points (profile completeness), engagement points (activity counts + recency), rule points (field-operator-value conditions). Supports manual override flag. Recalculates on create and update (if enabled).

| | |

### 1.27 Lead Starring (Favorites)

Toggle `isStarred` on a lead for personal reference.

| | |
|---|---|
| **API** | `PATCH /api/leads/[id]/favorite` |

### 1.28 Lead Health Insights

AI-style intelligence card: `healthScore`, `engagementScore`, `conversionProbability`, `lastResponseHours`, `recommendedAction`, `riskLevel` (low/medium/high).

| | |

## 2. Accounts

**Purpose:** Manage customer organizations with full relationship, health, and financial tracking.  
**Route:** `/accounts`  
**Primary permission module:** `accounts`  
**Database model:** `CrmAccount`

### 2.1 Account Creation

Fields: name, segment, segmentEnum (Enterprise/MidMarket/SMB), industry, website, status (Active/Prospect/Inactive), annualRevenueAmount/Currency/Display, address, healthScore (0–100), npsScore (−100–100), contractStart/End, renewalDate, tags (max 20), defaultPriceListId, parentAccountId.  
Auto-derives: ownerName from ownerId, industryKey (slug), formatted annualRevenueDisplay, segment text from enum. Prevents circular hierarchy on save.

| | |
|---|---|
| **API** | `POST /api/accounts` |
| **Permission** | `accounts:create` (blocked if user is ACL-restricted) |

### 2.2 Account Editing

PATCH with partial fields. Re-derives ownerName, industryKey, revenue display, segment text on change. Logs `AccountChange` activity. Validates no parent cycle if `parentAccountId` changes.

| | |
|---|---|
| **API** | `PATCH /api/accounts/[id]` |
| **Permission** | `accounts:edit` + account ACL |

### 2.3 Soft Delete & Restore

Sets/clears `deletedAt`. Both operations log an `AccountChange` activity in a transaction.

| | |
|---|---|
| **API** | `DELETE /api/accounts/[id]`, `POST /api/accounts/[id]/restore` |
| **Permission** | `accounts:delete` |

### 2.4 Permanent Delete (Admin only)

Hard-deletes the account. Nullifies `accountId` on linked leads, contacts, opportunities. Nullifies `parentAccountId` on child accounts. Must be in trash first.

| | |
|---|---|
| **API** | `DELETE /api/accounts/[id]/permanent` |
| **Permission** | Administrator role only |

### 2.5 Account List View

Paginated table. Tabs: All / My Accounts / Trash. Configurable sorting. My Accounts sorted by `renewalDate ASC NULLS LAST` then `name ASC`.

| | |
|---|---|
| **API** | `GET /api/accounts` |
| **Permission** | `accounts:view` |

### 2.6 Advanced Filter

Multi-condition filter on name, segment, industry, status, revenue, health score, contract dates, geography.

| | |
|---|---|
| **API** | `POST /api/accounts/filter` |

### 2.7 Account Picker (Embeddable)

Type-ahead `{id, name}` lookup for other forms. ACL-filtered.

| | |
|---|---|
| **API** | `GET /api/accounts/picker?q=&limit=` |

### 2.8 Account Detail Page (360 View)

Aggregated view: account record, parent + subsidiaries, dashboard snapshot (counts/metrics), timeline seed (activities, tasks, notes, call logs, opportunities, documents), score history.

| | |
|---|---|
| **API** | `GET /api/accounts/[id]/full` |
| **UI component** | `AccountDashboardShell` |

### 2.9 Linked Contacts Tab

View and manage contacts associated with the account. Quick-add contact from the tab.

### 2.10 Linked Leads Tab

View leads linked to account. Bulk-reassign selected leads to a new owner in a single transaction.

| | |
|---|---|
| **API** | `GET /api/accounts/[id]/leads`, `POST /api/accounts/[id]/leads/bulk-assign` |

### 2.11 Linked Opportunities Tab

Opportunities tied to account — name, stage, amount, probability, close date.

### 2.12 Linked Quotes Tab

Quotes tied to the account.

### 2.13 Account Hierarchy Tab

Display parent account and all subsidiary accounts. Parent-cycle prevention on edit.

### 2.14 Health Score Display

Integer field (0–100) with color-coded display. Used in health summary aggregation.

### 2.15 Health Summary Dashboard

Aggregate counts by health band (red < 40, amber 40–70, green ≥ 70), by status (Active/Prospect/Inactive), renewal windows (30/90 days). Filterable by owner, segment, health threshold.

| | |
|---|---|
| **API** | `GET /api/accounts/health-summary` |

### 2.16 Score Trends Tab

Historical health/NPS score over time as a chart.

### 2.17 Contract & Renewal Date Management

Fields: contractStart, contractEnd, renewalDate. Used in health summary forecasting. My Accounts list sorts by renewalDate.

### 2.18 Annual Revenue Tracking

Fields: `annualRevenueAmount` (numeric), `annualRevenueCurrency` (ISO 4217), `annualRevenueDisplay` (auto-formatted string).  
INR: lakh (₹L) and crore (₹Cr) units. Other currencies: K/M/B units.  
Free-text display field parses back to amount+currency on save.

| | |
|---|---|
| **Service** | `formatRevenueDisplay()`, `parseRevenueDisplay()` |

### 2.19 Account Tags

Free-form label array. Max 20 tags, each 1–64 chars.

### 2.20 Account Documents/Attachments

Upload, download, list, delete files attached to the account.

| | |
|---|---|
| **API** | `GET/POST /api/accounts/[id]/attachments`, download + delete routes |

### 2.21 Account ACL (Access Control)

Users scoped to a subset of accounts via direct grants (`crmUserAccountAccess`) or sales group membership. ACL Banner shown when restricted. Creation blocked for ACL-restricted users.

| | |
|---|---|
| **API** | `GET /api/accounts/acl-scope` |
| **Services** | `getScope()`, `assertAccountAccess()`, `accountScopeFilter()` |

### 2.22 Account Export

CSV/XLSX export with timezone-aware date formatting.

| | |
|---|---|
| **API** | `GET /api/accounts?format=csv\|xlsx` |

## 4. Opportunities

**Purpose:** Track potential revenue deals through a structured 6-stage sales pipeline.  
**Route:** `/opportunities`  
**Primary permission module:** `opportunities`  
**Database model:** `CrmOpportunity`

### Stage Definitions

| Stage | Probability | Terminal |
|---|---|---|
| Prospecting | 10% | No |
| Qualification | 25% | No |
| Proposal | 50% | No |
| Negotiation | 75% | No |
| ClosedWon | 100% | Yes |
| ClosedLost | 0% | Yes |

### 4.1 Opportunity Creation

Fields: name, accountId (required), leadId, stage, amount, currency (ISO 4217), probability, closeDate, ownerId, priceListId.  
Defaults: stage=Prospecting, probability=10%, currency=INR, owner=current user.  
Auto-computes `weightedAmount = amount × probability / 100`.

| | |
|---|---|
| **API** | `POST /api/opportunities` |
| **Permission** | `opportunities:create` |

### 4.2 Opportunity Editing

PATCH with partial updates. Re-computes `weightedAmount` on amount/probability change.

| | |
|---|---|
| **Permission** | `opportunities:edit` |

### 4.3 Soft Delete & Restore

Standard pattern.

| | |
|---|---|
| **Permission** | `opportunities:delete` |

### 4.4 Pipeline Kanban View

6-column drag-and-drop board. Stage-level totals by currency and INR headline. At-risk metrics per column (stuck deals, no-activity in 7 days, closing this month).

| | |
|---|---|
| **API** | `GET/POST /api/opportunities/pipeline` |
| **UI component** | `opportunity-kanban.tsx` |

### 4.5 Opportunity List View

Paginated table with search, filters, sorting. Export CSV/XLSX.

| | |
|---|---|
| **API** | `GET /api/opportunities` |

### 4.6 Advanced Filter

Multi-condition filter on name, accountName, stage, ownerName, amount, probability, currency, weightedAmount, closeDate.

| | |
|---|---|
| **API** | `POST /api/opportunities/filter` |

### 4.7 Opportunity Detail Page (360 View)

Tabs: Details, Products, Quotes, Stage History, Activities, Documents.

| | |
|---|---|
| **API** | `GET /api/opportunities/[id]/detail` |

### 4.8 Stage Transitions

Move between stages. Closing stages require `closeReasonCategory` from a predefined list. Force-transition available for Administrators only (`?force=true`). Creates `CrmOpportunityStageTransition` row + `CrmActivity` row. Updates `lastStageChangeAt`.

| | |
|---|---|
| **API** | `POST /api/opportunities/[id]/transition` |
| **Permission** | `opportunities:edit` |
| **Close reasons (Won)** | Price, Features, Implementation, Brand, Other |
| **Close reasons (Lost)** | Competitor, Price, No Budget, Lost to Status Quo, Bad Timing, Other |

### 4.9 Products on Opportunity

Add/edit/delete line items: quantity, unit price, discount %, notes, sort order. Auto-computes `lineTotal` per line. `?recalc=true` syncs opportunity `amount` from Σ line totals.

| | |
|---|---|
| **API** | `GET/POST /api/opportunities/[id]/products`, `PUT /api/opportunities/[id]/products?recalc=true`, `DELETE /api/opportunities/[id]/products/[productId]` |

### 4.10 Weighted Amount Forecast

`weightedAmount = amount × probability / 100`. Auto-computed on every save. Drives pipeline board forecast totals.

### 4.11 Multi-Currency Support

ISO 4217 currency per opportunity. Pipeline board shows INR-only headline total + `totalsByCurrency` array.

### 4.12 Opportunity Picker (Embeddable)

Type-ahead for other forms.

| | |
|---|---|
| **API** | `GET /api/opportunities/picker?q=&accountId=&limit=` |

### 4.13 Activity Timeline & Documents

Embedded `CrmActivity` timeline (relatedKind=`"Opportunity"`) and `EntityDocumentsCard` on detail page.

### 4.14 Account ACL Enforcement

`assertAccountAccess` gates all opportunity endpoints via linked `accountId`.

## 5. Quotes

**Purpose:** Generate, manage, approve, and send commercial proposals to customers.  
**Route:** `/quotes`  
**Primary permission module:** `quotes`  
**Database model:** `CrmQuote`, `CrmQuoteLine`

### Status Machine

```
Draft ──► Active ──► Won
                └──► Lost
                └──► Revised ──► (new Draft child)
```

### 5.1 Quote Creation

Fields: accountId, opportunityId, contactId, priceListId, currency, line items, dates (effectiveFrom/To), billingState/companyState, overallDiscountAmount, freightAmount, termsText.  
Auto-mints `QT-YYYY-NNNN` number (thread-safe `CrmSequence` lock). Computes all totals immediately.

| | |

## 19. Permissions & Access Control

**Purpose:** Enforce who can see and do what across all modules.

### 19.1 Role-Based Access Control (RBAC)

Hierarchy: Administrator (full access) → RBAC grants from `UserAppRole`/`RolePermission` → legacy permission templates → deny. Default CRM roles auto-seeded on first org access.

| | |
|---|---|
| **Service** | `loadUserCrmGrants(userId, orgId)` |

### 19.2 Module Permission Assertions

Every protected API route calls `assertModule(user, module, action)` → throws HTTP 403 if denied.  
All 16+ modules have defined actions: view, create, edit, delete, export, import, markComplete.

| | |
|---|---|
| **Functions** | `assertModule()`, `hasPermission()` |

### 19.3 Account-Level ACL

Users scoped to a subset of accounts via:
- Direct grants: `crmUserAccountAccess`
- Sales group membership: `crmSalesGroupMember/Manager` → `crmSalesGroupAccount`

Unrestricted if no ACL configured (backward-compat). Enforced on lead, contact, opportunity, and account queries.

| | |
|---|---|
| **Functions** | `getScope()`, `assertAccountAccess()`, `accountScopeFilter()` |

### 19.4 Field-Level Access Control

Hidden fields → returned as `null` from API (preserved in DB).  
Restricted fields → stripped from incoming PATCH/POST before DB write.  
Currently applied to Leads module.

| | |
|---|---|
| **Functions** | `maskHiddenLeadFields()`, `filterRestrictedLeadFields()` |

### 19.5 Permission Context Provider (Client-Side)

`PermissionProvider` wraps the dashboard. Exposes `usePermissions()` hook with `can(module, action): boolean` helper. Used to conditionally show/hide UI buttons and sections.

### 19.6 Price Floor Override Permission

`canOverridePriceFloor()` — admins always allowed; non-admins checked against RBAC grants for floor-override permission.

### 19.7 Legacy Permission Templates

`CrmPermissionTemplate` + `CrmUserPermissionTemplate` for field-level rules. Merged with RBAC grants (field visibility: most restrictive wins). Backward-compatible.
