Expect: the result is appended, the donut and the left-hand glyph update, and the next test opens. Shortcuts are ignored while typing, so a comment containing "1" won't record a pass.
Now record a second result on the same test. The first is not overwritten — both rows persist. Results are append-only: a correction is a new row, and the database refuses UPDATE and DELETE outright. Check GET /api/test/tests/<testId>/results to see the whole trail.

Click Close run in the runner header, then try recording another result.

Expect: the entry pane locks with "This run is closed, so its results are frozen." The API rejects further results with 409, so the freeze holds for scripts too, not just the UI. Reopen run unlocks it.

13CI ingestion — the automated write path

Mint a token with POST /api/v1/token, then report results keyed by automation ID. Requires TestResult:create — the same grant a human tester needs, so a token can never exceed a person's rights.

curl -X POST http://localhost:3004/api/test/runs/<runId>/results \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"results":[
        {"automationId":"login.spec.ts::valid_creds","status":"Passed","elapsedMs":1250},
        {"automationId":"ghost::missing","status":"Failed"}
      ]}'
Expect: {inserted: 1, unmatched: [{automationId: "ghost::missing", count: 1}]} — the known result lands, the unknown id is reported and persisted, and the batch does not fail. Unmapped tests are never silently dropped; see GET /api/test/runs/<runId>/unmatched.

Same store, different format — JUnit/xUnit XML:

curl -X POST http://localhost:3004/api/test/runs/<runId>/results/junit \
  -H "Authorization: Bearer <token>" -H "Content-Type: text/xml" \
  --data '<testsuite name="Login"><testcase classname="login.spec.ts" name="valid_creds" time="1.2"/></testsuite>'
Expect: the run flips to mixed once it carries both sources. Automated outcomes land on Automation Passed / Failed / Error, kept separate from the manual statuses so the donut's two columns stay meaningful. Malformed XML returns 400 with the line and column of the problem.

What this flow demonstrates

BehaviourWhy it matters
Version pinningA run shows the steps it actually executed, even after the case is edited.
Append-only resultsNo result is ever edited or deleted — enforced by a database trigger, not just application code.
One trail, two pathsManual and automated results share one table; source is the only difference.
Unmatched reportingA renamed CI test surfaces as a rising unmatched count instead of silently vanishing.
Closed-run freezeA finished run is a stable historical record.
