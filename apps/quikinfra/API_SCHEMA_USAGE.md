# QuikInfra — API & Database Schema Usage

> Reference doc. Reflects the repo's **current** state (after the legacy-route cleanup: the `masters/[entity]` catch-all, the store-GRN trio, and the singular `issue`/`transfer`/`reconciliation` approve aliases have been removed). Generated by static analysis — coverage is high because the codebase uses literal `/api/...` path prefixes, but anything reached purely through fully-dynamic URL construction would not be detected.

**How to read this.** Every API route is converted from its file path to its URL (`app` prefix and `/route.ts` stripped, `[param]` segments kept). **Methods** lists the HTTP verbs each `route.ts` exports (including `export const X = …` wrappers and re-exports like `export { handler as GET }`). **Status** is one of:

- **USED (app code)** — the URL is fetched/referenced from non-route source (`app/`, `src/`, `lib/`, hooks, components). Dynamic action suffixes (`/submit`, `/approve`, …) count as used when built via template literals (e.g. `` `/api/store/issues/${id}/submit` ``).
- **USED (tests only)** — referenced only under `__tests__/` (handler imported directly or URL constructed in a test), with no app-code caller.
- **USED (infra)** — platform/runtime endpoints (auth, health, ready, metrics, role provisioning) invoked by the framework/ops, not app code.
- **UNUSED** — no reference anywhere outside its own `route.ts`.

For DB models, **Status** mirrors this: **USED** = Prisma delegate (`db.cnXxx` / `tx.cnXxx`) queried in app code; **USED (tests only)** = delegate referenced only in tests; **USED (relation only)** = never queried directly, only reachable as a relation field on another model; **UNUSED** = no reference at all (dead).

## Dead / unused summary

### Routes with no app-code caller (tests only, or caller disabled)
No route is completely unreferenced, but these have **no live app caller** — candidates for removal or wiring:

- `/api/projects/[projectId]/rab/summary` — tests only.
- `/api/org/users/[id]/role` — tests only; app references it only in a comment (role swap runs through `/api/settings/users/[id]`).
- `/api/projects/dpr/weather` — tests only; caller in `DPRForm.tsx` is commented out.
- `/api/geo/opencage` — tests only; `OpenCageAddressAutocomplete.tsx` is disabled.
- `/api/debug/mail-test` — diagnostic endpoint, tests only.
- `/api/apps/switcher` — tests only; no in-app fetch found.

Functional dead-ends (wired to UI but **no persistence** — in-memory stubs): `/api/safety/incidents`, `/api/safety/toolbox-talks`.

### Models with zero references (dead)
- **`CnSafetyIncident`** — the only model with no delegate reference in app or test code. Its route (`/api/safety/incidents`) uses an in-memory array instead. Safe-to-drop candidate (pending a DB-backed safety-incidents feature).

### Models used only via relations (never queried directly)
Reachable only as `lines`/child arrays on a parent (expected for line-item tables): `CnPurchaseRequisitionLine`, `CnPurchaseOrderLine`, `CnPurchaseIndentLine`, `CnMaterialIssueLine`, `CnStockTransferLine`, `CnStockReconciliationLine`, `CnInternalReturnLine`, `CnGoodReturnLine`, `CnGatePassLine`, `CnRfqLine`, `CnRABLine`.

### Known correctness caveats (cross-reference)
- ⚠️ **`/api/store/issues/[id]/approve` does not deduct stock** — the live "Material Issue" screen (`/store/issue`) approves without writing the stock ledger/balance. Root cause: the `issues/*` module stores lines as denormalized JSON (`uomCode`, no `uomId`), incompatible with the ledger. See the stock-drift / material-issue notes.
- The four `*/post` store routes and `purchase/grn`, `projects/dpr` approve all correctly dual-write `Stock_ledger` + `Stock_balances` via `src/lib/stock/ledger-service.ts`.
